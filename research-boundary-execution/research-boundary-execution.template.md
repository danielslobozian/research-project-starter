# Research Boundaries input reference — execution only

**Version: 1.7b.10**

This retained source filename is an **input-reading reference**, not an RB creation template or a report outline. Read it with `research-boundary-execution.protocol.md`. The protocol governs defaults, legacy compatibility, evidence, output and delivery. The separate generation project creates RBs; this project does not fill placeholders, issue an RB or rewrite one.

## Identify the supplied contract

Use the actual metadata where present: `protocol_version` records the RB's creation version; `research_id` identifies the investigation; `rb_version` and `supersedes` identify its revision; `report_basename` supplies the artifact slug. `approval_status`, `approval_basis`, `approved_brief_id` and `approval_date` describe the supplied approval or waiver. A waived scope is `assumptions-not-explicitly-approved`, not approved. Do not infer a missing approval date or reconstruct a brief. An absent legacy field is not itself a reason to reject otherwise clear scope.

Read these nine content roles, allowing translated headings and legacy wording:

| RB section | What execution takes from it |
|---|---|
| 1. Research objective and motivation | The phenomenon and purpose, without assuming the motivating explanation is true. |
| 2. Primary research question | The exact primary question, normally Q0. |
| 3. Secondary research questions | Every accepted question and stable ID; no invented secondary-question quota. |
| 4. Included scope | Domains, populations/systems, cases, comparisons, dates and any fixed corpus. |
| 5. Exclusions | Non-goals and limits on generalization. |
| 6. Research approach and evidence expectations | The permitted review method, evidence, appraisal and access restrictions. Planned searches are not completed searches. |
| 7. Status of examples | Illustrative versus mandatory; examples do not silently narrow or expand the question. |
| 8. Deliverable contract | Audience, language, explanation depth, purpose, reader context (absent in RBs before 1.7b.10: none), exact reader/source filenames, additional formats, citations, visuals, reference layout, length/tolerance and known capability limits. |
| 9. Assumptions, uncertainties and open boundaries | Unresolved scope/access assumptions, not established findings. |

Use the protocol's [start and scope rules](research-boundary-execution.protocol.md#start) for missing legacy axes, exact RB preservation, the legacy PDF-plus-HTML case, explicit presentation changes and unresolved conflicts. Explicit accepted fields take precedence over defaults. A report format does not determine which evidence is relevant. Keep all question-level answers and consequential support when adapting the report to its reader.

The issued RB remains the standalone scope artifact. Actual searches, results, access failures and stopping reasons belong in the report and working notes, never in a retroactively edited RB.
