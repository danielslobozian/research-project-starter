What the runs show

Use the stronger settings, and know your app.

SETTINGS

On ChatGPT at Medium and Instant, and on Claude Haiku at Low, the generation project was skipped: a simple-looking question got a direct answer, with no reader questions and no brief. The higher settings followed the engine.

MISTRAL VIBE

The “Thinking” setting runs GLM-5 (glm-5-latest-short, a model Mistral hosts), not a Mistral model. Vibe turns every question into a multiple-choice popup: type your own answer in its free field. Vibe cannot render PDFs, so ask for HTML reading copies.

CLAUDE FABLE 5.1

At Max, Fable 5.1 treated the project instructions as a prompt injection, because the app delivered them inside a tool result, and answered directly.

READER QUESTIONS

Every app that followed the engine asked its reader questions first: at most four, open, each with a default, and never took the answers as approval of the brief.

Method

How these runs were made.

One run per case and app, on one day, with engine 1.7b.10 installed as two projects in each app. Nothing was re-run: a run that answered directly or delivered a broken file is reported as it ended. The settings differ from case to case on purpose, from the lightest (case 5) to the strongest (cases 3 and 4).

The person running the cases followed these rules:

  1. Send the opening message exactly as written, as the first message of a new chat in the generation project.
  2. Answer only what the assistant asks, using the card's facts, in a few plain words. Do not volunteer card facts it did not ask about.
  3. If it asks something the card does not cover, answer "No preference."
  4. If the brief gets a card fact wrong, correct it once, in one sentence. Otherwise reply "approved".
  5. Download every file the generation chat gives (the RB) and every file the execution chat gives.
  6. In the execution project, open a new chat, attach the RB, and send it with no text.
  7. Share both conversations (public link) and note the links in the run log.

Each delivered run was then checked automatically: the Research Boundaries file, the reader-context fields, the format, the language, page limits, self-contained HTML and the absence of personal details. The checks and their results are with each run. The definitions are in cases.json and the run summaries in runs.json.
