Research engine · v1.7b.10

Two projects. One file between them.

The generation project turns your question into an approved Research Boundaries (RB) file. The execution project researches that file and delivers the report. Each project is a block of instructions and two files, in any assistant that has projects, web search and file creation.

01 / Generation project

From your question
to an approved RB.

It does not research. Before approval it may run a handful of searches to learn the vocabulary, but it does not read or report findings: the scope is not anchored on early results.

Step 1You ask, in your own words

A question, a worry, a claim to check. Examples you give are treated as illustrations unless you make them mandatory.

Step 2Capability check and reader questions

It checks what this app can do (web, files, PDF, code) and names any fallback. Then it asks up to four open questions about the reader, each with the default it will use, and stops.

Step 3A brief of about 350 words

A neutral main question (Q0), supporting questions, boundaries and exclusions, the evidence expected, and one deliverable line: audience, depth, purpose, reader context, format, length. At most three open points, each with its assumption.

Step 4Approval issues the RB

Correct the brief as often as you like; each revision gets a new brief ID. “approved” issues the RB file with nine sections, from the objective to the deliverable contract and the assumptions. A new question or boundary is shown again before it is approved.

02 / Execution project

From the RB
to a report.

Open a new chat in the execution project, attach the RB and send it with no text. One assistant does everything in that one conversation; it does not change the RB's scope.

Step 5Investigate the questions

Search and read within the RB's scope and method, appraise the evidence that drives conclusions, and weigh counter-evidence. Each question ends with an answer, an investigated inconclusive result, or a disclosed evidence gap.

Step 6Write for the reader

The RB's purpose decides what leads (a decision, an explanation for others, a claim to check and cite); the reader context decides which evidence is emphasised. Numbered citations point to inspectable source locations.

Step 7Render and measure

The reading copy (self-contained HTML, or PDF) is rendered from the Markdown source. The body length is measured in the reference layout, or reported as “unverified”.

Step 8Reconcile, then deliver

The claims that drive conclusions are rechecked against their sources. You receive the reading copy, the Markdown source, the unmodified RB (and a ZIP when there are figures), with two stated outcomes: research complete or not, delivery complete or partial.

03 / Install

Two projects,
three files each.

Download the release, or open each file below. In every app, create two separate projects.

Generation project

Instructions and two files

Project instructions: paste the whole of research-boundary-generation.instructions.md.

Project files: upload research-boundary-generation.protocol.md and research-boundary-generation.template.md, keeping their names.

Execution project

Instructions, two files, tools on

Project instructions: paste the whole of research-boundary-execution.instructions.md.

Project files: upload research-boundary-execution.protocol.md and research-boundary-execution.template.md, keeping their names.

Tools: enable web search, file reading and file creation. Code execution helps with PDF checks; an HTML report needs no converter.

Keep the projects apart. Never put both sets of instructions in one project, and do not upload the README or the change log: they are documentation.

Per app, from the recorded cases

ChatGPT

Use a Thinking setting at High or above. At Medium and Instant, a simple-looking question was answered directly, without the engine.

Claude

Opus and Sonnet followed the engine. Haiku at Low answered directly; Fable 5.1 at Max treated the project instructions as a prompt injection.

Mistral Vibe

“Thinking” runs GLM-5 (glm-5-latest-short). Its questions come as multiple-choice popups: type your own answer in the free field. Ask for HTML: Vibe cannot render PDFs. Prefer the ZIP package: in case 1, an HTML file downloaded from Vibe on its own came with an analytics script added by its file hosting.

04 / Use

Five steps,
two chats.

  1. In the generation project, describe what you want to know, in your own words.
  2. Answer the reader questions as far as you like; “skip” uses the stated assumptions.
  3. Read the brief; correct it, or approve it with “approved”. The RB is issued as a file.
  4. In the execution project, open a new chat, attach the RB, and send it with no text.
  5. You receive the report as HTML (or PDF if you asked for it), its Markdown source for tools, and the RB.

To revise the research later, go back to the generation project: a material change is a new brief and a new RB. Explanatory follow-up questions about a delivered report can be answered within its scope.

05 / Limits

A research method,
not a guarantee.

The app decides whether to follow it

Project instructions are a request to the model. In the cases, five of fifteen runs answered directly instead.

The model checks its own work

Source rechecks, page measurement and rendering checks are done by the same assistant, and reported as performed or not performed. They are not independent verification.

Access limits evidence

Paywalled or blocked sources are disclosed, not cited from memory. A failed retrieval is not evidence that a study does not exist.

06 / Since 1.6

What changed.

  • Two projects instead of one. Agreeing the research and carrying it out are separate projects, joined only by the RB file.
  • Reader questions. Before the first brief, up to four open questions about the reader and the use; the answers are recorded in the RB.
  • Reader context. A new RB field for the reader's situation where it makes some evidence more applicable; it shapes emphasis, not scope.
  • A reading copy by default. Every report comes as a self-contained HTML (or PDF) to read, with the Markdown as source for tools.

The 1.6 engine, its guide and its live examples remain available: choose v1.6 in the version menu, or download the v1.6 release.
